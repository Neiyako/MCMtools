## 题目与做法

Wordle 的结果分享格式让每个玩家都成了自愿的数据上报者。题目要求解释
结果如何传播、并预测未来的上报量。

我们把过程建成四仓室传播模型 **PCQL**：在标准 SIR 之外增加
*Quitted*（退出者）和 *Loyal*（忠实玩家）两个仓室。

**扩展的动机来自数据，不是来自"更一般所以更好"**：

- 标准 SIR 的移出仓是终态的，一旦玩家停止就永不回来
- 因此 SIR 必然让活跃度衰减到零
- 而观测序列在峰值后**缓慢**下降且**从不归零**

加上 Loyal 仓室后，衰减由"厌倦流失"与"回流补充"两个速率共同决定，
而不是仅由易感者耗尽决定 —— 这才产生了数据要求的形状。

## 主要结果

| 量 | 值 |
|---|---|
| 决定系数 R² | 0.8202 |
| RMSE | 35,947 条/天 |
| 传播率 β | 0.3131 /天 |
| 厌倦率 γ | 0.001147 /天 |
| 基本传播数 R₀ | 273.1 |

敏感性分析（单因子，固定其余三个参数）：β 从 0.20 升到 0.45，
预测峰值日从第 59 天提前到第 29 天；**峰值高度几乎不变**。
结论：传播率控制的是**何时**见顶，不是**多高**。

## 明说的失败

模型预测峰值在第 40 天，数据在第 93 天。我们没有把它调掉，
而是追到原因：恒定传播率假设下，每个活跃玩家从到达起就同等"有传染性"，
而现实里单词难度表让玩家**分批**加入。均质混合模型没有延迟自身增长的
机制，所以接触率一够就饱和。残差图里的系统性符号模式就是这个误差的痕迹。

实用的补救写进了论文：**用模型估 R₀ 和衰减形状，绝对时间以观测峰值为锚**。

## 数据说明

原题的 Twitter 数据文件没有随题提供，这里的 `data/` 是按同样的结构
（按日期汇总的各次数分布）合成的时间序列，用于实测工具链。
论文里的数字全部来自这份合成数据的真实拟合结果，不是编的。
数据集登记时 `source.kind` 标的是 `simulated`，没有假装是官方数据。
