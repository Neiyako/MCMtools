# 建模手使用指南

你负责：**把赛题拆成模型，定义符号、公式、假设、参数**，并保证每个量都有来源。

代码手按你的定义写代码，论文手按你的定义写正文。
你这层的定义不清楚，后面两层都会歪。

> 工具还没跑起来？先看 [README 快速开始](../README.md)，
> 或整段复制[现成的部署提示词](AGENT_PROMPTS.md)让 AI 助手替你装好。

---

## 一、你实际要做什么

面板上四个页面：

| 页面 | 你填什么 |
|---|---|
| 「数学内容」 | 符号、公式、假设、目标与约束 |
| 「参数」 | 参数名、值、单位、**来源** |
| 「数据」 | 数据集登记（列名、类型、缺失值） |
| 「实验」 | 实验协议（要变哪个参数、变几次） |

**定义清楚比写得多重要。** 一行符号定义含糊，代码手就得猜。

---

## 二、第一步：拆题

别急着建模型。先把题目拆开：

1. **题目给了什么** —— 数据、约束、要回答什么
2. **分成几个子问题** —— 每个子问题要单独建个模型
3. **每个子问题的输入输出** —— 上一个的输出是不是下一个的输入

在「选题」页把读题笔记写下来。**写详细点不吃亏** ——
写 Introduction 的时候能直接翻。

### 判断题型

| 题型 | 特征 | 常见模型 |
|---|---|---|
| 数据类（C） | 给数据集，要你分析预测 | 回归、时间序列、聚类 |
| 机理类（A） | 物理/生物过程，要推导 | 微分方程、守恒律 |
| 评价类（E） | 要排序、打分、决策 | AHP、TOPSIS、熵权 |
| 政策/运筹（B/D） | 要出方案、做调度 | 优化、排队、博弈 |

`templates/models/` 有 17 个模型骨架可以对照：

```
优化类    optimization_lp  mip_scheduling  game_theory
预测类    prediction_regression  prediction_timeseries  regression_advanced
评价类    evaluation_ahp  evaluation_topsis  statistical_inference
动态类    ode_system  differential_discrete  cellular_automata  markov_chain
其他      queueing  graph_network  classification  simulation_abm
```

看某个骨架的设计思路：

```bash
./core/mcm template show model.ode_system
```

## 三、符号表

「数学内容」页 →「符号」→ 填：

| 字段 | 说明 | 例子 |
|---|---|---|
| 符号 | LaTeX 写法 | `S_t` |
| 含义 | 中文解释 | 第 t 天的累计存活人数 |
| 角色 | 见下表 | `state` |
| 单位 | 有量纲就填 | 人 |
| 取值范围 | 可选但建议填 | `[0, N]` |

### 角色必须填对

论文里的符号表**按角色分组**，这是评委看的第一张表。

| 角色 | 含义 |
|---|---|
| `state` | 状态量，随时间变的 |
| `parameter` | 参数，建模时定死的 |
| `decision` | 决策变量，你能选的 |
| `derived` | 派生量，算出来的 |
| `exogenous_data` | 外部输入数据 |
| `output_metric` | 输出指标（要优化的那个） |
| `index` | 下标、序号 |

**同一个符号不能重复定义。** 审计会报 `SYMBOL_REDEFINED`。

## 四、公式

「数学内容」页 →「公式」→ 填 LaTeX 和说明。

### 角色（EquationRole）

| 角色 | 什么时候用 |
|---|---|
| `governing` | 支配方程，模型的核心 |
| `definition` | 定义式 |
| `constraint` | 约束 |
| `objective` | 目标函数 |
| `transformation` | 变换式 |
| `metric` | 指标计算式 |
| `calibration` | 标定/拟合式 |

### 写公式的规矩

1. **每个公式有编号**，正文要引用（"由式 (3) 得……"）
2. **首次出现的符号必须能查到** —— 在符号表里
3. **推导步骤别跳** —— 机理类题目评委盯推导
4. **量纲要一致** —— 两边单位对不上是硬伤

---

## 五、假设

「数学内容」页 →「假设」→ 每条填内容和适用范围。

### 写法

**不要只列假设，要写为什么。**

| 不好的写法 | 好的写法 |
|---|---|
| 假设词频独立 | 假设每日词频相互独立。理由：Wordle 每日答案由官方独立选取，历史词频不影响未来选词。这一假设在长周期（>60 天）可能失效。 |

### 适用范围

每条假设标适用到哪：`paper`（全篇）/ `model`（某个模型）/ `subproblem`（某个子问题）。

### 假设会变成参数

如果某个假设引入了一个数值（比如"假设平均猜词次数为 4"），
**这个值要登记成参数**，来源选 `assumed`。

## 六、参数——这层最关键

「参数」页填每个参数的**来源**。这是诚实性问题，不是格式问题。

### 七种来源

| 来源 | 含义 | 论文里怎么写 |
|---|---|---|
| `literature` | 来自已发表文献 | 引文献 |
| `dataset` | 从数据直接算出 | 说明数据来源 |
| `fitted` | 拟合得到 | 写清拟合方法和误差 |
| `derived` | 由其他量推算 | 给出推算过程 |
| `assumed` | **假设值** | **必须说明这是假设** |
| `semi_educated_guess` | 半经验估计 | 说明依据和不确定性 |
| `unknown` | 不知道 | 尽量避免 |

**把假设值写得像测量值，是建模论文最常见也最严重的毛病。**

### 参数表要能回答三个问题

1. **这个值哪来的** —— 来源
2. **准不准** —— 有区间就给区间
3. **不准会怎样** —— 这就是敏感性分析要回答的

### 敏感性分析

**这是拉开差距的一节。** 评委必问"参数不准会怎样"。

在设计实验时就要想好：

- 哪个参数最可能不准 → 重点扫它
- 扫多大范围 → 至少覆盖合理的不确定区间
- 看什么输出 → 选你最关心的指标

用「实验」页的 `exp.sensitivity_oat`（单因子）或
`exp.sensitivity_grid`（双因子看交互）。

审计会检查：有敏感性实验但没有不变的基准？
报 `SENSITIVITY_WITHOUT_INVARIANT`。

## 七、数据

「数据」页填**文件的完整路径**，工具自动读出：

- 几行几列
- 每列是数字还是文本
- 每列多少缺失值

**这些数字审计要用，别手抄**，抄错了审计就失去意义。

### 来源如实选

| 选项 | 什么时候选 |
|---|---|
| 比赛方提供 | 题目附件里的数据 |
| 外部数据 | 网上找的、数据库导出的 |
| 衍生数据 | 自己清洗/计算出来的 |
| **模拟数据** | **自己生成的** |

**模拟数据必须标明是模拟的。** 论文里这几类写法不一样。

## 八、模型验证

建完模，至少做一种验证：

| 方法 | 什么时候用 |
|---|---|
| 留出法 | 有足够数据，留 20% 不参与建模 |
| 交叉验证 | 数据少，用 k 折 |
| 统计检验 | 要说明差异显著 |
| 内部一致性 | 多个方法结果互相印证 |
| 与文献对比 | 有公开的基准值 |

**不验证会被审计报 `NO_VALIDATION`。**

验证结果要写进论文，包括**没达到预期的部分**。

## 九、和另外两个人的交接

### 给代码手

- 符号、公式、参数定义要能直接翻译成代码
- 参数名用英文、无空格（`hard_mode_weight`），别用中文
- 说清楚哪个参数要扫、扫多大范围

### 给论文手

- 符号表填全（论文自动生成）
- 假设写清理由（直接进正文）
- 参数来源如实标（决定正文怎么写）
- 模型取舍讲明白（论文的 Model 一节）

---

## 十、诚实性硬要求

1. **模拟数据标 `simulated`**
2. **假设值标 `assumed`** —— 不能混在测量值里
3. **失败的结果保留** —— 模型预测不准就写清偏了多少
4. **不为了好看调参** —— 调参数去凑一个漂亮结果，是学术不端

> 一个真实例子：某次峰值预测，模型算第 40 天，实际第 93 天。
> 这个失败原样保留在报告里，没有调参掩盖。
> 建模比赛里，"知道自己的模型在哪儿不行"是加分项。

## 十一、命令速查

```bash
# 看符号表
./core/mcm --dir ~/mcm/2026A math show

# 看参数及来源
./core/mcm --dir ~/mcm/2026A param list

# 项目状态与待处理问题
./core/mcm --dir ~/mcm/2026A overview

# 审计
./core/mcm --dir ~/mcm/2026A validate

# 看模型骨架的设计思路
./core/mcm template show model.optimization_lp
```
