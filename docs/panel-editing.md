# 面板编辑与自定图表

面板以前只能"看"。数学内容和参数两页是只读表格，想改一个符号释义
得去翻 `math/math.yaml` —— 这就是"去根目录修改也很麻烦"的来源。

现在这两页都能直接改，另外加了一个不写代码的自定义生图页。

---

## 改数学内容

侧栏「数学内容」页。符号、公式、假设三类都能增删改。

### 符号

| 字段 | 说明 |
|---|---|
| 符号 | 论文里的写法，如 `beta`。**同一个符号只能有一个含义**，重复会被审计报错 |
| 含义 | 直接生成到论文符号表，所以要写英文完整表述 |
| 类别 | 状态量 / 参数 / 导出量 / 变量 / 下标 / 常数 |
| 单位、取值范围 | 可不填 |

### 公式

只写公式本身，**不要写 `\begin{equation}` 和 `\label`** —— 编号和标签由系统加。
写了会重复编号，编译时报 `Multiple \label's`。

### 假设

每条假设都要给理由。只写"假设参数恒定"是没写完 —— 要说明为什么可以这么假设。
`适用范围` 决定它进论文的哪一段。

---

## 改参数

侧栏「参数」页。每个模型常数都在这里登记，**没登记的数字在正文里没有出处**。

重点是**来源**这一栏：

| 来源 | 什么时候用 |
|---|---|
| 文献 | 从某篇论文查到的，在「来源说明」写清哪篇哪张表 |
| 数据 | 从数据集直接算出来的 |
| 拟合 | 由实验拟合得到，填「拟合自」哪个实验 |
| 假设 | 找不到出处，主动假设的 —— 要能说出依据 |
| 推导 | 由其他参数推出来的 |
| 半经验估计 | 有量级依据但没严格来源 |

留空或标 `未标注` 的参数，在 `--strict` 审计下会**阻塞提交**。
这是故意的：一个没交代出处的数字是论文里最容易被评审质疑的地方。

取值可以留空 —— 表示"还没定"。留空的参数也会被审计报出来，
这同样是好事，说明它确实还没定。

---

## 自定图表

侧栏「自定图表」页。**不写代码**，点选拼图。

### 三个分区

左边**外观**：图形类型（27 种）、配色（6 套）、标题、轴名、尺寸、网格/图例开关。

中间**数据**：直接粘一串数字即可。

```
10, 32, 58, 74, 61, 30
```

逗号、空格、中文逗号都认。横轴留空就自动用 1,2,3…

右边**预览**：实时出图，改完立刻能看到。

### 支持哪些图

折线、折线+数据点、散点、柱状、条形、分组柱、堆叠柱、面积、堆叠面积、
阶梯、火柴梗、饼图、环形、直方图、箱线、小提琴、误差棒、误差带、
热力图、等高线、三维曲面、双对数、半对数、极坐标、帕累托、瀑布、雷达。

### 几个实用细节

- **误差棒 / 误差带**：在「误差值」填每个点的不确定度，个数要和数据一样
- **参考线**：填「水平参考线」画一条虚线，标出目标值 —— 评审最容易看懂的表达
- **雷达图自动归一化**：量纲不同的指标直接画会全被最大的那个压平
- **瀑布图自动配色**：增量绿、减量红，自动算累计值
- **帕累托图自动排序**：降序排列并画出 80% 线

### 存成模板

画好后点「存成模板」，起个名字（英文或数字）。它会被写进
`templates/figures/diy_<名字>/`，和内置模板平级 ——
之后就能在「生图工作台」里找到它、绑到实验上、进论文。

存的是**规格**而不是一张 PDF，所以同一个图能换数据反复用。

## 数据格式

生图工作台的数据框支持两种写法。

**只给一组数据**（大多数人的第一反应，直接这样写就行）：

```json
{ "y": [10, 32, 58, 74] }
```

**多序列**：

```json
{
  "series": [
    { "name": "方案A", "y": [10, 32, 58, 74] },
    { "name": "方案B", "y": [8, 24, 41, 55] }
  ]
}
```

不确定要填哪些键？点「填入示例数据」—— 数据框下面会列出**这个模板
需要哪些键、每个键什么意思、给一个能直接用的示例值**：

```
values（必填，要统计分布的数值）=[1.0, 1.8, 2.6, 3.4, 4.2, 5.0]
bins（可选，数值参数）=6
fit_curve（可选，参考曲线）=[2.0, 3.36, 4.72, ...]
```

这份说明是从模板自己的声明推导的，不是手写的 —— 所以新加的模板
自动就有，不会过期。

## 出错时会怎样

数据填错不会得到一个看不懂的报错。比如 x 和 y 长度不一致：

> 第 1 个序列：x 有 3 个点，y 有 2 个，必须一样多。

模板和 DIY 页共用一个原则：**说清哪里错了、差多少、怎么改**。
一个 `KeyError: 'y'` 对正在比赛的建模队员是没法处理的。

---

## 中文与字体

图里的中文需要中文字体。系统会自动挑一个装上
（PingFang SC / Hiragino Sans GB / Heiti SC…），并把负号换成 ASCII
—— 中文字体没有真减号 `−`，不换的话坐标轴上的负数是方块。

`R²` 这类上标也会被转成 `R2`，因为中文字体没有 `²` 字形。
要在图里用正规上标，用 `$R^2$` 让 matplotlib 走数学字体。

机器上没有中文字体时，DIY 页顶部会给出提示，不报错 ——
你仍然可以画英文图。

## 一个已修的隐蔽故障

正文里曾经出现 `\numBeta{}` 被换行劈成 `\numBeta{}` 相邻两行的样子。
LaTeX 的报错是：

```
Undefined control sequence
l.64 \numRSquared
```

这句话**完全不指向真正的原因**。实际病灶是早先一次批量编辑吃掉了
宏名前的反斜杠，剩下的 `n` 又和旁的字面 `\n` 拼在一起，
存档里就成了 `\n\numBeta{}`。

现在渲染前会先整理一遍正文（`renderer.normalise`）：

1. 把行内数学 `$...$` 里的换行收成空格 —— LaTeX 的行内数学不能跨空行
2. 把被劈开的宏名接回去（`umBeta` → `\numBeta`）

顺序不能反：先修宏的话，第二步收换行时会把刚补上的反斜杠
一起吞掉。这个顺序是踩出来的，测试里有专门的用例盯着。

所以**已经写坏的存档也能自愈** —— 你不用为了改一句话去手工编辑 YAML。
