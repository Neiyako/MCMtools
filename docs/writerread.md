# 论文手使用指南

你负责：**把建模和计算结果写成能拿奖的论文**，并保证正文里每个数字都跟代码一致。

MCM/ICM 的论文有硬性页数限制（近年是**总共 25 页**），
所以"写多少"和"写什么"同样重要。

---

## 一、你实际要写什么

面板会给你搭好章节骨架，**你只填正文**。

```
paper/
├── paper.yaml      章节列表 + 正文（★ 你写正文）
└── refs.bib        参考文献
```

页数、章节顺序、符号表、参考文献表由工具排版，你不用管。

---

## 二、写论文的顺序

### 1. 先选题型骨架

面板「论文」页有四种骨架，按题型选：

| 骨架 | 适用题型 | 章节逻辑 |
|---|---|---|
| `spine_data_driven` | C 题（数据类） | 描述数据 → 建模 → 预测 |
| `spine_physical` | A 题（机理类） | 守恒律 → 推导 → 数值验证 |
| `spine_evaluation` | E 题（评价类） | 指标体系 → 赋权 → 排序 → 验证 |
| `spine_policy` | B/D 题（政策/运筹） | 方案 → 评价准则 → 推荐 |

**为什么按题型分**：不同题型的评委关注点不一样。
评价类看"指标体系立不立得住"，机理类看"推导和数值验证"，
数据类看"数据处理质量"。骨架就是把这些关注点排进章节顺序。

### 2. 生成骨架

```bash
./core/mcm --dir ~/mcm/2026A paper spine      # 写章节骨架
./core/mcm --dir ~/mcm/2026A paper scaffold   # 补空骨架（不覆盖已写正文）
```

`scaffold` **不会覆盖你已经写的正文**，所以随时可以补。

### 3. 逐章填正文

面板「论文」页点章节标题展开，直接改。

### 4. 编译

点「生成 PDF」。页数实时显示在右上角（`18/25 页`）。

## 三、最重要的一条：数字不要手写

**正文里出现数字，一律用宏引用。**

```latex
Wordle 的预测精度为 \numScore{}，RMSE 为 \numRMSE{}。
```

宏名在面板「结果」页能看到，复制即可。

### 为什么

改一个参数重跑实验，**正文自动跟着变**。
手写数字的话，改完要满篇找 —— 漏一个就是"正文说 0.82、
代码跑出来 0.79"，审稿人一眼能看出来。

### 宏名怎么来的

由结果原子的 ID 生成：

```
RES-0142   →   \numRESZeroOneFourTwo{}
```

**数字被拼成英文单词不是排版讲究**，是 LaTeX 的硬限制 ——
控制序列只能是字母，`\numRES0142` 不合法。

填了短别名的原子更好写：

```
macro_alias: score   →   \numScore{}
macro_alias: r2      →   \numR2{}     （别名里的数字会被丢掉）
```

### 不是结果数字怎么办

页数、题目字母这类固定值，用 `\lit{1}` 明确标为例外：

```latex
本题为 \lit{C} 题，共 \lit{3} 个子问题。
```

不标的话审计会报 `NUMERIC_UNBOUND`（正文里有没绑定来源的数字）。

## 四、章节里该写什么

### 摘要（Summary）

**最重要的一页**，很多评委只细看摘要。结构：

1. 问题是什么（一句）
2. 用了什么方法（一句，说清方法名）
3. 得到什么结果（**给出关键数字**）
4. 结论有什么意义

不要写"本文研究了……"这种话。直接给结论。

### 假设（Assumptions）

每条假设要写**为什么这么假设**，不是只列假设。
评委看的是"你知不知道自己做了什么简化"。

假设要能追溯到「数学内容」页登记的条目。

### 符号表（Notations）

工具按角色自动分组（状态量 / 参数 / 决策变量 / 派生量）。
你只要在「数学内容」页把符号和角色填全。

### 模型（Model）

- **先给整体思路**，再进公式。别一上来堆符号
- 每个公式给编号，正文要引用
- 变量首次出现必须解释
- **建模的取舍要写出来**：为什么选这个不选那个

### 敏感性分析（Sensitivity）

**这是拉开差距的一节。** 评委必问"参数不准会怎样"。

写清楚：哪个参数最敏感、变化多少输出变多少、结论稳不稳。

### 优缺点（Strengths & Weaknesses）

优点别吹，缺点别藏。
写"模型在什么条件下不适用"比写"本模型精度高"得分高。

## 五、图表

### 图

「生图工作台」38 个模板，支持中文搜索（搜"时间"、"分布"、"热力"）。

流程是**先填数、再预览**：

1. 选模板
2. 填数据
3. 点预览 —— 后端真渲染 PDF，不是示意图

**图上中文不会出豆腐块**（中文字体已配好），
**文字不会互相压住**（有自动检测）。

模板里没有的图型，用「自定图表」点选拼接，覆盖 27 种。

### 表

「表格」页 13 个表模板：描述统计、参数表、结果对比、
敏感性排序、误差分析等。

### 图表的硬规则

1. **每张图必须在正文里被引用**（"如图 X 所示"），
   否则审计报 `ARTIFACT_NOT_CITED`
2. **图要有图注**，说清画的是什么、单位是什么
3. **坐标轴必须有标签和单位**
4. **数据来源要交代**：模拟数据要在图注里写明是模拟的

## 六、参考文献

### 导入

从 Google Scholar / 知网 / Zotero 复制 BibTeX，粘贴到「参考文献」页。

### 核对

工具会检查正文引用和文献表对不对得上：

- 引了但没列出 → 报错
- 列了但没引 → 报错

**请自己核实每条文献真实存在。** 工具能核对格式和引用关系，
但没法替你确认这篇论文真的存在。

### AI 工具的使用

如果你用 AI 工具查了文献或辅助写作，**如实标注**。
工具的 AI 合规检查会记进 `ai_usage` 报告。

比赛规则越来越在意这个，主动说明比被查出来好。

## 七、页数控制

总共 25 页是**硬限制**，不是建议。

### 页数怎么省

| 手段 | 省多少 |
|---|---|
| 图并排（两张小图一行） | 明显 |
| 表格用小字号 | 中等 |
| 删掉重复的公式推导 | 中等 |
| 附录放代码，正文只留关键片段 | 大 |

### 页数不够

少于 20 页通常说明内容单薄。检查：

- 敏感性分析写了吗
- 模型验证写了吗
- 优缺点讨论写了吗

---

## 八、交付前检查

1. **页数在 25 页内**（右上角实时显示）
2. **没有 `NUMERIC_UNBOUND`** —— 所有数字都绑了来源
3. **每张图表都被正文引用**
4. **符号表没有未定义符号**
5. **参考文献引用关系闭合**
6. **没有占位符**（`TODO`、`XXX`、`待补`）
7. **摘要里有具体数字**，不是空话

面板「审计」页会把这些逐条列出来。

> **不是所有提示都要改。** 判断标准是能不能解释清楚：
> 能解释的是风格选择，不能解释的才是问题。

导出在「论文」页，打包到项目 `export/` 下。

## 九、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 编译报 `Undefined control sequence` | 宏被换行劈开了 | 工具会自动修，还报就检查 YAML |
| 正文数字对不上代码 | 手写数字没走宏 | 换成 `\numXxx{}` |
| 审计说 `ARTIFACT_NOT_CITED` | 图没在正文引用 | 加一句"如图 X 所示" |
| 页数超了 | 通常是图太大 | 图并排或缩小 |
| 导出 PDF 缺字体 | 系统缺中文字体 | `./core/mcm doctor` |

```bash
# 写章节骨架

./core/mcm --dir ~/mcm/2026A paper engine

# 审计
./core/mcm --dir ~/mcm/2026A validate
```
