# 使用指南

从零到交出论文的完整操作。每一步都写清**点哪里、填什么、会看到什么**。

> 命令行的等价写法在 [README](../README.md) 里。这份文档只讲面板，
> 因为比赛期间你更可能点鼠标而不是敲命令。

---

## 第 0 步：启动

```bash
cd MCMtools
./start ~/mcm/2026A          # 项目目录不存在会自动创建
```

浏览器会自动打开 `http://127.0.0.1:8xxx`。

**项目目录不要放桌面。** macOS 会拒绝从 App 双击启动时读取
`~/Desktop`、`~/Documents`、`~/Downloads` 下的文件 —— 这是内核级的
权限限制，从终端启动没事，双击 `.app` 就会读不到。
放 `~/mcm/` 或 `~/Projects/` 下最省事。

启动前可以自查：

```bash
./start --check      # 只检查环境，不启动
./core/mcm deploy    # 检查目录完整性、数模板个数
```

---

## 第 1 步：选题

侧栏「选题」。

1. 填**题号**（A–F）和**标题**，点「+ 登记」
2. 六道题都登记进来，边读边排除
3. 决定之后，点那行的「锁定」

**锁定前想清楚**：锁定后侧栏会收窄到建模流程。锁错了到「设置」页
点「解锁题目」就能退回选题阶段 —— 已经产出的结果不会删，只会显示为
过期。

**队伍控制号**可以在这里填，也可以之后到「设置」页补。它印在摘要页上。

> 题目列表、每道题的读题笔记都存在项目目录的 `problems/` 下。
> 笔记写详细点不吃亏 —— 写 Introduction 时能直接翻。

---

## 第 2 步：导入数据

侧栏「数据」。

填**文件的完整路径**，点「导入」。工具会自己读出：

- 有几行几列
- 每列是数字还是文本
- 每列有多少缺失值

**这些数字后面审计要用**，所以不要手抄 —— 抄错了审计就失去意义。

**来源**要如实选：

| 选项 | 什么时候选 |
|---|---|
| 比赛方提供 | 题目附件里的数据 |
| 外部数据 | 网上找的、数据库导出的 |
| 衍生数据 | 自己清洗/计算出来的 |
| 模拟数据 | 自己生成的 |

选错会让论文里的数据可信度说不清。论文中这几类的写法不一样，
**模拟数据必须写明是模拟的**。

目前支持 CSV / TSV（UTF-8 编码）。别的格式先转一下。

---

## 第 3 步：写数学内容

侧栏「数学内容」。四类东西，每类都有「+ 新增」：

| 类型 | 填什么 | 例子 |
|---|---|---|
| 符号 | 符号、含义、角色、单位、取值范围 | `N` / 总天数 / parameter / 天 |
| 公式 | LaTeX 公式、编号、说明 | `S_t = S_{t-1} - I_t` |
| 假设 | 假设内容、作用范围 | 假设词频独立 / paper |
| 目标与约束 | 目标函数、约束条件 | — |

**符号的「角色」要认真填**（状态量 / 参数 / 决策变量 / 派生量）。
符号表按角色分组，是评委看的第一张表。

填完看一眼有没有重复符号 —— 工具会提示。

---

## 第 4 步：定参数

侧栏「参数」。

每个参数填：名字、值、单位、**来源**。

来源四选一，和数据的来源一样要如实：文献 / 数据 / 拟合 / 假设。

**「假设」是要在论文里明说的**。把假设值写得像测量值，
是建模论文最常见也最严重的毛病。

---

## 第 5 步：做实验

侧栏「实验」。

### 最快路径：套模板

「套模板」下拉里有九种常见实验设计：

| 模板 | 什么时候用 |
|---|---|
| `exp.sensitivity_oat` | 每次只动一个参数（最常见） |
| `exp.sensitivity_grid` | 两个参数同时变，看交互 |
| `exp.model_comparison` | 几个模型比精度 |
| `exp.robustness_noise` | 加噪声看结果稳不稳 |
| `exp.monte_carlo` | 随机模拟，要置信区间 |
| `exp.cross_validation` | 交叉验证 |
| `exp.convergence_study` | 画收敛曲线 |
| `exp.scenario` | 情景分析 |
| `exp.train_test` | 训练/测试划分 |

选一个，填个名字，点「创建实验」。

### 填变动参数

**这一步决定实验会不会真的"多次运行"。**

在「变动参数」里填：

- 参数名：`hard_mode_weight`
- 取值：`0.1, 0.5, 1.0`（逗号分隔）
- 单位：可选

**留空的参数保持不变。** 填了变动参数，实验才会真的跑多次，
出图才有横轴。不填的话只会跑一次。

### 写运行脚本

创建完实验后，在项目目录下建脚本：

```
experiments/EXP-001/run.py
```

```python
def run(trial: dict) -> dict:
    """收到一个参数字典，返回结果原子。

    trial 是本次试验的参数，例如 {'hard_mode_weight': 0.5}。
    """
    w = trial["hard_mode_weight"]
    score = 1.0 / (1.0 + w)          # 你的模型写在这里

    return {"atoms": [
        {"name": "score",            # 必填：名字
         "value": score,             # 必填：数值
         "macro_alias": "score",     # 可选：正文里写 \numScore{}
         "direction": "higher_is_better",   # 可选
         "unit": ""},                # 可选
    ]}
```

然后在实验协议里指向它（面板建的协议里 `entrypoint` 字段）：

```yaml
entrypoint: experiments/EXP-001/run.py:run
```

冒号后面是**函数名**。

### 返回值的确切格式

**必须包在 `{"atoms": [...]}` 里**，不能直接返回 `{"score": 0.79}`：

| 返回 | 结果 |
|---|---|
| `{"atoms": [{"name": "score", "value": 0.79}]}` | 正确，产生结果原子 |
| `{"score": 0.79}` | 静默产生 **0 个**原子（会被当成"metrics"以外的键忽略） |
| `[{"name": ..., "value": ...}, ...]` | 也可以，直接给列表 |
| `None` | 不产生原子 |

每个原子的字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 结果名，会进原子 ID |
| `value` | 是 | 数值 |
| `atom_id` | 否 | 不填则自动生成，形如 `RES-EXP001-SCORE-001` |
| `macro_alias` | 否 | 短宏名。填了正文里写 `\numScore{}`；不填就得写长名 |
| `direction` | 否 | `higher_is_better` / `lower_is_better` / `neutral` |
| `unit` | 否 | 单位 |
| `renderings` | 否 | 备用渲染，如 `{"pct": "79.1\\%"}` → `\numScorePct{}` |

> **两个容易踩的点**：
>
> 1. **整份参数字典作为"一个参数"传入**（`fn(dict(trial))`），
>    不是展开成关键字参数。和多数人的直觉相反。
> 2. **`direction` 的合法值只有那三个**，写成 `higher_better` 会报错。
>    报错信息很明确，照着改就行。

**验证跑通了没有**：跑完到「结果」页看有没有原子。一个都没有的话，
多半是返回格式不对 —— 看 `runs/EXP-001/<运行号>/stderr.txt`。

**没有脚本就跑不了**。点「运行」时会提示你需要补 entrypoint ——
这是有意的，工具不会替你猜。

`templates/code/` 下有 16 个可直接复制的脚本骨架（敏感性分析、
蒙特卡洛、ARIMA、熵权 TOPSIS……），拿来改比从零写快。

### 运行

回到实验页点「运行」。跑完后：

- 「运行记录」页能看到每次运行的完整归档
- 「结果」页能看到产生的**结果原子** —— 这就是正文要引用的数字

## 第 6 步：出图

侧栏「生图工作台」。38 个图模板，可以按中文搜（搜"时间"、"分布"、"热力"）。

流程是**先填数、再预览**：

1. 选模板
2. 填数据（页面会给样例格式，照着改）
3. 点预览 —— 后端真的渲染出 PDF，不是示意图

**图上中文不会出豆腐块**：中文字体已经配好。

图上文字也不会互相压住 —— 有一组自动检测在盯着这件事。

### 模板里没有想要的图型？

用侧栏「自定图表」：点选图型 + 数据 + 样式，不用写代码。
覆盖 27 种图型。

> 为什么不做"贴代码执行"：比赛期间你是建模的人不是程序员，
> 贴进来的代码报错自己没法调；而且那等于开了个任意代码执行的口子。

---

## 第 7 步：写论文

侧栏「论文」。

1. 点「生成 PDF」先看看骨架
2. 点章节标题展开，直接改正文

**正文里不要手写数字**，用宏：

```latex
Wordle 的预测精度为 \numRESOneZeroZeroOne{}，RMSE 为 \numRESOneZeroZeroTwo{}。
```

宏名在「结果」页能看到，复制就行。

**为什么值得这么麻烦**：改一个参数重跑，正文自动跟着变。
手写数字的话，改完要满篇找 —— 漏一个就是"正文说 0.82、
代码跑出来 0.79"，审稿人会抓住。

页数预算是实时的（右上角 `2/25 页`）。2022–2025 年的获奖论文里，
72% 正好是 25 页。

---

## 第 8 步：审计与交付

侧栏「审计」。它会扫出：

- 正文里没绑定来源的数字
- 引用了但没定义的符号
- 从没被正文引用的图和表
- 页数不够 / 超了
- 参考文献的问题

**不是所有提示都要改**。判断标准是能不能解释清楚 ——
能解释的就是风格选择，不能解释的才是问题。

导出在「论文」页，打包到项目的 `export/` 下。

---

## 参考文献

侧栏「参考文献」。

**导入**：从 Google Scholar / 知网 / Zotero 复制 BibTeX，粘贴进去。

**核对**：工具会检查正文引用和文献表对不对得上 ——
引了但没列出、列了但没引，都会报出来。

如果你用了 AI 工具查文献，**如实标注**。工具的 AI 合规检查会
把这件事记进 `ai_usage` 报告；比赛规则越来越在意这个，
主动说明比被查出来好。

> 请自己核实每一条文献真实存在。工具能核对格式和引用关系，
> 但没法替你确认这篇论文真的存在。

## 比赛期间的注意事项

**全部本地运行，不联网。** 这是设计目标 —— 比赛那几天网络会断、
额度会用完、服务会排队。

「设置」页能看到当前的运行模式：

- **开发模式**：可以用 AI 辅助，赛前准备用
- **竞赛模式**：拦截网络访问、拒绝 AI 辅助命令

这不是记录意图，是真的强制。

**开工前先备份项目目录**：

```bash
cp -r ~/mcm/2026A ~/mcm/2026A-backup
```

项目目录里全是纯文本（YAML + Markdown + Python），
出问题能直接读、直接改、能进 git。

## 卡住了怎么办

```bash
./core/mcm report --out diag.txt
```

生成诊断报告：版本号、系统、依赖、模板数、项目结构计数。
**不含论文正文** —— 只报数量不报内容。

拿到报告先看三件事：

1. **版本对不对** —— `0.5.0+git.a1b2c3d` 能直接定位
2. **模板数够不够** —— 少于 101 就是拷贝不完整，不是代码问题
3. **依赖齐不齐** —— 没有 pdflatex 只是不能出 PDF，别的照常

### 几个常见的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 面板某页空白 | 该页没注册进路由表 | 报 bug，附诊断报告 |
| 图上中文变方块 | 系统缺中文字体 | `./core/mcm doctor` |
| 编译报 `Undefined control sequence` | 宏被换行劈开了 | 工具会自动修，还报就手工看 YAML |
| 点「运行」提示没有 entrypoint | 还没写运行脚本 | 见第 5 步 |
| 从 .app 启动读不到文件 | 项目在桌面，被系统权限挡住 | 把项目移到 `~/mcm/` |

## 命令速查

```bash
./start ~/mcm/2026A                # 启动
./start --check                    # 只检查环境
./core/mcm deploy                  # 部署自检
./core/mcm report --out diag.txt   # 诊断报告
./core/mcm template list           # 列出模板
./core/mcm --version               # 版本 + git 提交号
```

项目内操作（`--dir` 指定项目）：

```bash
./core/mcm --dir ~/mcm/2026A exp run EXP-001   # 跑实验
./core/mcm --dir ~/mcm/2026A paper build       # 编译论文
./core/mcm --dir ~/mcm/2026A validate          # 审计
```
